# CallStats — статистика операторов для FreePBX 16

Дата: 2026-10-21
Статус: черновик на согласование

## 1. Зачем

Владельцу колл-центра на FreePBX 16.0.50 нужен свой аналог Asternic Call Center Stats PRO, но только в той части, которой он реально пользуется: понимать, как работает каждый оператор, и слушать разговоры каждого оператора отдельно. Asternic Lite (github.com/asternic/asternic-stats-lite) изучен как образец: устарел (PHP 5.4, Prototype.js), без авторизации, без записей, считает только очереди. Asternic PRO (архив `asternic-stats-pro-2.3.19.tgz` в папке проекта) — коммерческий, код зашифрован ionCube и помечен «not redistributable»; **код из него не копировать**, использовать только как подтверждение подхода (queue_log + CEL).

Успех: пользователь открывает сервис в браузере на Windows-компьютере, выбирает оператора и период и сразу видит цифры, ленту его дня и список его разговоров с кнопкой «слушать».

## 2. Пользователь

Один пользователь — владелец (решение пользователя). Ролей и разграничения прав нет. Интерфейс только на русском.

## 3. Что входит (три функции)

### 3.1 Статистика операторов

Таблица за выбранный период, одна строка на оператора, строка «Итого» внизу.

Фильтры: период (пресеты «Сегодня», «Вчера», «Эта неделя», «Прошлая неделя», «Этот месяц», «Прошлый месяц» + произвольные даты), очередь/группа (необязательно), выбор операторов (по умолчанию все).

Столбцы (сортировка по любому — это и есть «рейтинг лучших/худших»):

| Столбец | Смысл |
|---|---|
| Оператор | внутренний номер + имя |
| Принято | входящих звонков, на которые ответил этот оператор |
| Пропущено | звонило этому оператору, он не ответил (правило подсчёта — п. 5.3) |
| % ответа | Принято / (Принято + Пропущено) |
| Не в сети | сколько звонков пришло, когда телефон оператора был выключен / не зарегистрирован |
| Исходящие | звонков, совершённых с внутреннего номера оператора, и сколько из них состоялось |
| Время разговоров | сумма длительности входящих + исходящих разговоров |
| Средний разговор | по входящим отвеченным |
| Среднее время до ответа | сколько в среднем звонило у оператора, прежде чем он взял трубку |
| Время в системе | время между входом и выходом в очередь (только для динамических участников очередей; иначе «—») |
| Время на паузе | сумма, с разбивкой по причинам во всплывающей подсказке или раскрытии строки (только очереди) |

Клик по оператору открывает его журнал (3.2) за тот же период.

### 3.2 Журнал оператора

Выбор: оператор + дата (по умолчанию сегодня) или диапазон дат. Сверху — сводка за выбранный период (те же цифры, что в 3.1). Ниже — хронологическая лента событий:

- вход в очередь / выход из очереди (с названием очереди);
- пауза: начало, конец, причина, длительность;
- входящий принят: время, номер клиента, откуда пришёл (очередь X / группа Y / прямой), сколько звонило до ответа, длительность разговора, кнопка «слушать», если есть запись;
- входящий пропущен: время, номер клиента, откуда пришёл, сколько звонило;
- исходящий: время, номер, состоялся ли, длительность, «слушать»;
- перевод: кому перевёл / от кого получил.

Пример того, как должно читаться:
`09:02 Вход в очередь «Продажи» → 09:05 Принят +7 701 …, очередь «Продажи», ждал 12 с, говорил 3:15 ▶ → 10:30–10:45 Пауза «Обед» (15 мин) → 11:12 Пропущен +7 777 …, группа «Офис», звонило 20 с → 18:01 Выход`

### 3.3 Записи разговоров

Выбор: оператор (или все) + период. Фильтры: номер клиента (поиск по части номера), длительность от/до (например «длиннее 15 минут»), направление (входящие/исходящие/все), очередь/группа.

Таблица: дата и время, направление, номер клиента, оператор, очередь/группа, длительность, плеер.

Плеер — прямо в строке, в браузере, без скачивания: воспроизведение/пауза, перемотка по шкале, громкость, скорость (1×, 1.5×, 2×). Рядом кнопка «скачать». Одновременно играет только одна запись.

## 4. Не входит (non-goals)

Живое табло, рассылка отчётов на почту, SLA, анализ причин потерь по очереди, путь звонка (call flow), графики нагрузки, несколько пользователей и роли, экспорт в Excel/PDF. Их можно добавить позже, архитектура не должна этому мешать, но делать их сейчас не надо.

## 5. Откуда данные

### 5.1 Источники (только чтение)

| Источник | Где на FreePBX 16 | Что берём |
|---|---|---|
| queue_log | файл `/var/log/asterisk/queue_log` | события очередей: ENTERQUEUE, CONNECT, RINGNOANSWER, ABANDON, COMPLETEAGENT/COMPLETECALLER, TRANSFER, ADDMEMBER/REMOVEMEMBER, AGENTLOGIN/AGENTLOGOFF, PAUSE/UNPAUSE (с причиной) |
| CDR | БД `asteriskcdrdb`, таблица `cdr` | все звонки: Ring Groups, прямые, исходящие; длительности; `recordingfile`; `linkedid`/`uniqueid` |
| CEL | БД `asteriskcdrdb`, таблица `cel` | события каналов, чтобы точно понять, у кого звонило и кто ответил в Ring Group |
| Справочник операторов | БД `asterisk`, таблица `users` (extension, name) | имена внутренних номеров |
| Справочник очередей и групп | БД `asterisk`: `queues_config`, `ringgroups` | названия |
| Записи | `/var/spool/asterisk/monitor/ГГГГ/ММ/ДД/` | аудиофайлы, путь собирается из даты звонка и `cdr.recordingfile` |

Сервис **никогда не пишет** в базы и файлы FreePBX. Для чтения заводится отдельный пользователь MariaDB с правом SELECT на `asteriskcdrdb` и нужные таблицы `asterisk`.

### 5.2 Сборщик

Скрипт по cron раз в минуту забирает новые данные в собственную БД сервиса `callstats` и раскладывает их в готовые для отчётов таблицы (звонок, попытка дозвона до оператора, сессия входа, пауза).

- queue_log читается инкрементально: запоминаются inode и смещение; ротация файла (logrotate) обрабатывается — дочитать старый, начать новый.
- CDR/CEL читаются по возрастанию id / времени с запасом назад (звонки, которые ещё не закончились, досчитываются при следующем проходе).
- Повторный запуск не создаёт дублей. Должна быть команда полной пересборки с нуля за указанный период (если поменялась логика подсчёта).
- Одновременно работает только один экземпляр (блокировка).
- **Первичная загрузка истории** *(моё решение)*: при установке загружается всё, что есть на сервере: текущий и ротированные файлы queue_log (включая `.gz`), весь CDR и CEL. За периоды, где CEL не было, звонки Ring Group считаются по CDR в упрощённом режиме, а в отчётах за такие дни показывается пометка «данные по группам приблизительные».

### 5.3 Правила подсчёта

- **Оператор = внутренний номер FreePBX.** В queue_log участник может называться по-разному (`Local/101@from-queue/n`, `PJSIP/101`, `SIP/101`, имя «Иванов»); всё приводится к номеру 101. Если сопоставить не удалось — оператор показывается отдельной строкой «как есть», а не теряется.
- **Принят** — оператор взял трубку (CONNECT в очереди; в Ring Group/прямом — по CEL/CDR его канал соединился с клиентом).
- **Пропущен** *(моё решение, уточнено по реальным данным, п. 10)*: один звонок клиента = максимум один пропуск у оператора. Пропуск засчитывается, если у оператора **реально звонило** (телефон был в сети, время звонка > 0) **и звонок в итоге никто не взял**. Это одно правило для очередей, Ring Group и прямых звонков.
  - Звонок, который взял коллега, остальным в пропуски не идёт; в журнале виден серым как «звонило N с, взял другой».
  - Телефон не в сети (RINGNOANSWER с временем 0 — у этой АТС так на каждом звонке для 1005, 1009, 1010) — не пропуск. В журнале и статистике отдельно: «телефон был не в сети: N звонков».
  - Повторные круги очереди (`retry`) по одному звонку дают один пропуск, а не несколько.
- Если в очереди клиент положил трубку, пока у оператора ещё звонило (в queue_log только ABANDON), это **не** пропуск оператора *(моё решение)*. В журнале оператора такая попытка видна как «клиент положил трубку, звонило N с», если по CEL удаётся установить, что звонило именно у него.
- **Сопоставление каналов с операторами**: кроме `PJSIP/101`, `SIP/101` и `Local/101@…` нужно учесть Follow Me и вызов на мобильный (Local/trunk-канал) и привязать такой ответ к оператору, чей номер вызывался. Фактическую настройку (статические или динамические участники, Follow Me, внешние номера в группах) смотреть на реальных данных (п. 10).
- **Перевод**: разговор до перевода засчитывается первому оператору, после — второму.
- Внутренние звонки оператор↔оператор в статистику «Принято/Исходящие» не входят *(моё решение)*, но видны в журнале.
- Паузы и время в системе есть только у участников очередей. Для остальных — «—», не ноль.
- Время — часовой пояс сервера FreePBX.

Цифры могут не совпадать с отчётом CDR в FreePBX один в один — потому что CDR считает каналы, а мы звонки. Для отладки на странице звонка в журнале должна быть возможность увидеть, из каких исходных записей он собран.

## 6. Как устроено (решения)

- **Где работает**: на том же сервере FreePBX 16 (SNG7), отдельный сайт `https://<сервер>/callstats/`, не внутри админки FreePBX и не модуль FreePBX (решение пользователя: «свой сервис»).
- **Стек** *(моё решение, пользователь не возражал)*: PHP 7.4, MariaDB, Apache — то, что уже стоит на FreePBX 16. Никаких новых языков, демонов и Node.js на сервере. Все JS/CSS-библиотеки лежат локально в проекте (у сервера может не быть интернета).
- **Размещение**: код вне каталогов FreePBX (например `/opt/callstats`), в Apache — только `Alias /callstats` на его папку `public/`. Обновления FreePBX не должны ломать сервис и наоборот.
- **Вход**: логин и пароль одного пользователя, пароль хранится хешем, сессия, ограничение попыток входа. Без входа недоступно ничего, включая файлы записей.
- **Отдача записей**: только через PHP-обработчик по id звонка (не по пути из URL), с проверкой сессии, поддержкой HTTP Range (чтобы работала перемотка). Форматы FreePBX по умолчанию — WAV; если встретятся форматы, которые браузер не играет (gsm и т.п.), — показать «скачать» вместо плеера.
- **Установка**: один скрипт установки: создаёт БД и пользователей MariaDB, конфиг, Alias в Apache, cron; и `README` на русском с шагами, включая проверку, что CEL включён (Settings → Advanced Settings → Enable CEL Reporting) и что запись разговоров включена.

## 7. Ограничения и масштаб

- FreePBX 16.0.50, Asterisk 16/18, PHP 7.4, MariaDB 5.5/10.x — проверить фактическую версию на сервере при установке.
- Масштаб неизвестен; ориентир — до 100 операторов, до 10 000 звонков в день, история за несколько лет. Отчёт за месяц должен открываться за пару секунд.
- Нагрузка на FreePBX минимальная: сборщик читает только новое.
- Пользователь смотрит с Windows в современном браузере (Chrome/Edge); мобильная версия не нужна, но таблицы не должны ломаться на узком окне.

## 8. Анти-цели (провал, даже если «работает»)

- Сервис что-то изменил в FreePBX, его БД или конфигах, или сломался после обновления FreePBX.
- Запись разговора можно открыть по ссылке без входа или подобрав путь к файлу.
- Цифры «Пропущено» выглядят завышенными из-за Ring Group, и пользователь перестаёт им доверять.
- Звонки оператора теряются, потому что он записан в очереди под другим именем.

## 9. Оставлено на усмотрение исполнителя

Структура БД `callstats`, фреймворк или его отсутствие (с учётом PHP 7.4), библиотеки для таблиц и плеера, внешний вид (простой, аккуратный, деловой), способ тестирования. Для проверки правил подсчёта нужны тестовые наборы queue_log/CDR/CEL, покрывающие: очередь, Ring Group «звонить всем», прямой звонок, перевод, исходящий, паузу с причиной, ротацию queue_log.

## 10. Реальные данные (получены 2026-10-21)

Пользователь выгрузил с сервера образец за 3 дня: `D:\Call Center\samples\callstats-sample\` (содержит номера клиентов — только локально, в git не добавлять). Тестовые наборы строить из него. Прямого SSH-доступа нет (сервер удалённый, порты снаружи закрыты) — установка и проверка на сервере выполняются пользователем по готовым командам.

Что на сервере:

- Sangoma Linux 7.8, FreePBX 16.0.50, **Asterisk 18.26.4**, PHP 7.4.16, **MariaDB 5.5.65** (старая: нет оконных функций, JSON-функций и т.п. — запросы писать под 5.5). Часовой пояс сервера Asia/Tashkent (+05).
- Одна рабочая очередь **1000 «Bananza»**: стратегия `ringall`, timeout 15 с, retry 5 с, запись включена. Участники **статические**: `Local/1001…1005,1009,1010@from-queue/n`. Входов/выходов и пауз в queue_log нет — операторы ими не пользуются.
- Ring Groups **нет**. Follow Me включён у всех, но звонит только на сам внутренний номер. Внешних номеров в очереди нет.
- Внутренние номера 1001–1012 (PJSIP), все телефоны из одного офиса. Транк `552020515`. **Имена операторов в FreePBX не заданы** (имя = номер).
- В queue_log есть событие `RINGCANCELED` (Asterisk 18: перестало звонить, потому что ответил другой) и `DID`.
- CDR: «Log unanswered calls: No», данные с 2026-08-18. CEL включён (все события, ODBC) с 2026-01-12, ~5,5 млн строк.
- Записи: `/var/spool/asterisk/monitor/ГГГГ/ММ/ДД/`, WAV, имена `q-1000-<номер>-…` (очередь), `out-<номер>-<внутр>-…` (исходящие). Есть файлы по 44 байта — пустые (только заголовок WAV): плеер для них не показывать, писать «запись пустая».
- На сервере уже что-то пишет `queuestats_syncall.log` / `queuestats_purnedata.log` в `/var/log/asterisk/` — другой инструмент статистики. Не трогать и не зависеть от него.

Следствия для сервиса:

- **Имена операторов**: в сервисе страница «Операторы», где можно задать имя каждому внутреннему номеру (хранится в БД `callstats`); если имя в FreePBX появится — показывать его, пока не задано своё.
- Столбцы «Время в системе» и «Время на паузе» показываются, только если за период есть такие данные; сейчас их не будет. Код для них всё равно нужен (операторы могут начать ставить паузы).
- «Принят» в очереди — по `CONNECT`; прямой входящий — по CEL/CDR (`ext-local`, ANSWERED).
